# How Switchboard works

Switchboard has three parts on your Mac:

- the account engine, which keeps each account's login, makes each switch and reads each account's limits. It lives in `switchboard/accounts` and uses only Python's standard library;
- [the page](#the-page), which a background job keeps running. It keeps new logins, keeps every account's numbers current ([how fresh](#how-fresh-the-numbers-are)) and runs auto-switch;
- the `switchboard` command and [the menu bar item](#the-mac-app). The command works without the page; the menu bar item reads the page.

## Accounts

An account is one Claude login, kept in your Keychain ([Privacy](#privacy) says where).

You add one by signing in to it with `/login` in Claude Code. Claude Code moves to that account, as `/login` always does, and Switchboard keeps the login while the page runs. `switchboard add` does the same, one sign-in at a time.

An account you remove stays out: signing in to it again does not bring it back. `switchboard add` does.

Switchboard tells one login from another by the login itself, not by the email Claude Code shows. When the two disagree, it shows that instead of guessing. An account is marked as needing a sign-in only when Anthropic refused its login, the login has lapsed, or Anthropic says the login kept for it is another account's (then it is never put in use): never because the Keychain was slow or locked.

Switchboard renews your logins by itself, so an account keeps working without you. Anthropic ends each sign-in by a set date, and renewing does not move it: only signing in again does. The date is the latest it ends: a sign-in can end any time in the three days before it. Switchboard shows that date a week ahead, under the account on the page ("Sign-in ends by Wed 1:15 AM"), in the menu bar, in `switchboard` and in `switchboard doctor`, and a notification comes 3 days and 1 day before the earliest it can end. Until it ends the account works as usual, auto-switch included. Claude Code shows the same for the account it is on: `claude auth status --text`. To sign in again, press Sign in to all above the accounts (its line shows while a sign-in has ended or ends within the week, and counts them): it signs in again to each of those, and to any that ends well before the others, one after another, each in its own browser profile, and you approve each in the tab that opens. Its hover names each account it opens, in that order. Accounts signed in together end together, so the next time is again one press. Sign in on a row does the same for one account, and `switchboard signin` does it from a terminal. The account Claude Code is on signs in the same way: Claude Code moves to its new sign-in at once, and if a Claude Code window puts its older sign-in back, Switchboard puts the newer one back. Switchboard only opens each sign-in page; you sign in and approve it there yourself. Once the date has passed, the account needs a sign-in, and the page says when it ended.

`switchboard alias` gives an account a short name, such as `work`, to use in place of its number or email.

## A switch

Claude Code reads its login from one Keychain item, `Claude Code-credentials`, and the account's name from `~/.claude.json`. A switch:

1. reads the login in use and saves it under its own account first, so a login Claude Code renewed is never lost. If the Keychain can't be read, the switch stops before writing anything;
2. holds Claude Code's own lock files, so a token refresh in Claude Code can't land halfway;
3. writes the other account's login into that item, and its name and organization into `~/.claude.json`, leaving everything else in that file as it was;
4. reads both back, and puts the old login back if they don't match.

Your chats, settings and projects stay as they are. A switch that was cut off part-way is finished or undone the next time Switchboard starts, from what Claude Code's login really holds, and History says which. One that could not be settled then (the Keychain was locked, say) is settled by a later pass of auto-switch or by the page's own check, one at a time.

Claude Code can also lose its sign-in by itself: when many open chats save its Keychain item at once (right after a switch, say), the item can be left without the login while Claude Code's settings still name the account. Switchboard looks for that, every few seconds for 3 minutes after a switch and once a minute otherwise. When it holds a saved login for the account the settings name, it puts that login back within seconds, says so in History and in a notification ("Claude Code lost its sign-in. Switchboard put … back."), and never renews that login with Anthropic while it is lost. It never undoes a sign-out you chose (the settings then name nobody), never puts back the account a switch just left, never writes over a login that is there, and leaves an item kept in a form it does not know. Each time within an hour it waits longer first, and after the fourth it stops and History asks you to run `/login` in Claude Code once. When the item itself was gone, your claude.ai connector logins don't come back with it: sign in to those again. When Claude Code stays without a sign-in for 5 minutes that Switchboard could not put back, while auto-switch is on, one notification says so, with the one thing to do: on the page, press Use on an account, or Sign in on the account Claude Code was on.

Outside a switch, Switchboard writes the account's name and organization into `~/.claude.json` in one case only. A Claude Code session that was open during a switch can write the earlier name back a moment later, and Claude Code then shows one account while it works as another. When the settings have named another account than the login for 20 seconds, Switchboard makes them name the login's account again, under the locks a switch takes, at most 6 times an hour, and History says so.

## What follows a switch

| | After a switch | Why |
|---|---|---|
| A new Claude Code session, in a terminal or VS Code | Starts on the new account | It reads its login from the Keychain item a switch rewrites. |
| A Claude Code session already open | Moves within about 30 seconds | Claude Code reads its login again after about 30 seconds. If one stays on the old account, restart it; in VS Code, start a new chat. |
| An artifact or doc a session made | Stays with the account that made it | An artifact that is not shared opens only for the account that published it. A chat that gets "not found" is told which account owns it and the command that opens it ([Artifacts](#artifacts)). |
| A claude.ai connector a chat uses (Google Drive, Linear, Slack…) | Belongs to the account that added it | Connectors are added per account on claude.ai, and calls made just after a switch can fail ("session expired", "is not connected"). The chat is told what Switchboard knows: where the connector last answered, which account the chat is on, whether that account has had it answer on this Mac in the last 7 days, and the way through ([Session hooks](#session-hooks)). |
| What the chat said and did, and the model's private reasoning | The conversation stays; earlier reasoning may not | Anthropic's newest models use reasoning from earlier in a chat only in the account that produced it; in another account it is dropped, with no error. Everything said and done stays, and the first request after a switch reads it all again. |
| The Claude desktop app | Keeps its own sign-in | It has a sign-in of its own, which a switch does not change. Its Code tab may share Claude Code's login; that has not been checked. |
| claude.ai in your browser | Keeps its own sign-in | Each browser profile has its own. Switchboard opens an artifact in the profile of the account that owns it. |

## Artifacts

An artifact that is not shared opens only for the account that published it; anyone else sees "Page not found". Switchboard knows an artifact's owner from when it was published: each publish is stamped with a time, and Switchboard knows which account Claude Code was on then. It proves the owner by reading the title of the tab it opened. A real title means the right account; "Page not found" means it closes that tab, tries the next profile, and remembers what worked.

A page made a moment ago opens as its owner too. The [session hooks](#session-hooks) note each publish as it happens. The page takes that note within seconds and passes it on to the small file the link app reads, so the Artifacts list and a clicked link know the owner; `switchboard open` and `switchboard owner` read the note themselves, even when the page is not running. A page published within 90 seconds of a switch is only a guess, since an open session can still be on the old login then; the first open checks it in the browser.

Where Switchboard has one, the Artifacts list shows a preview: a picture of your own page, made on this Mac from the file Claude Code published. Soon after a publish, while that file is still there (a session's temporary folder is emptied within days) and unchanged since, Switchboard opens it once in headless Chrome, in a temporary profile of its own that is removed after (never one of your profiles), and keeps a small JPEG of it in `~/.switchboard/previews`, which only you can read. The page may load only what a published artifact may load, the code and font sites claude.ai allows; nothing else on the internet is reached, and the picture stays on this Mac. Pages known from before get one too, when their file is still on disk. Without Chrome there is no picture, and the list shows the page's title instead. At most about 500 pictures (50 MB) are kept, the oldest going first, and a picture goes when its artifact is no longer listed.

To open an artifact as its owner:

- `switchboard open LINK`, or one click on its tile in the page's Artifacts. `switchboard owner LINK` names the owner without opening anything.
- Switchboard Links, the link app, for links you click anywhere. Set as your default browser, it sends a claude.ai artifact to its owner's profile and everything else to the browser you used before. When the page is slow or not running, it opens the link in the owner's profile from a small file the page keeps, never in whichever window was used last. The installer builds it when Apple's command line tools are there (`switchboard update --link-app` adds it later), and the first run asks macOS once to make it your default browser; until it is, the page offers one button for that. `switchboard links off` gives the seat back.
- For links clicked inside the browser, the page's "Open as owner" bookmark.

A proof doesn't last forever. Once a day Switchboard quietly opens one page per account to prove its profile again, and a profile that shows another account or a sign-in page is marked and tried last. An account with no browser profile signed in to claude.ai says "No Chrome profile is signed in as this account", with a Set up button that opens claude.ai's sign-in page in a new profile for it. Switchboard never signs anything in or out.

A Claude Code session that gets "not found" from an artifact or a Claude Doc is told which account owns it and the exact commands: `switchboard open LINK` to see it in the owner's profile, and `switchboard run OWNER -- -p "…"` to work on it as that account. It is never told to sign in.

To read tab titles, Switchboard needs macOS's permission to control Chrome. The page asks macOS whether it may, instead of guessing from a slow answer, and lets macOS ask you only when you press Let Switchboard check links or Check now, or run `switchboard check`. A command run in a terminal while the page is not running reads the tabs itself, so macOS asks about the terminal. Links are tested with Chrome only. Brave and Edge use the same code but have not been tried.

## Chats

`switchboard chats` shows what is going on in each account. For each account: the chats on it now (working means the chat or one of its helpers wrote in the last 5 minutes; idle, in the last day), the chats that started there and are on another account now, its turns in the last day, and the claude.ai connectors that have answered under it. For each chat: its title, folder and id, the account it started under, the account it is on and since when, how many times it moved, and what it holds that belongs to another account: pages it made there, and connectors that answered it there, with whether the account it is on now has had that connector answer on this Mac.

It comes from each chat's own file. Claude Code writes into it the login the chat started under, and a line each time the login it is on changes. So Switchboard knows a chat's account from the chat itself, not from when it switched. A chat on an organization Switchboard doesn't keep is shown as one, never dropped. The page's background job reads the chats written in the last 7 days, a bounded amount at a time and newest first, then once a minute only what was added. `switchboard chats` takes a short look of its own, so it works when the page is not running, and says how many chats it has read when it has not read them all yet. The page's own view of it is `GET /api/chats`, and each account in `GET /api/state` carries its counts (`chats`: on, working, elsewhere).

How exact it is:

- Claude Code writes the line at a chat's first request after the login changed. "Here since 2:21 AM" is that chat's first request on that account, not the moment of the switch.
- A chat that has been quiet since a switch still names the account of its last request. Its next request goes to the account Claude Code is on, unless it has a login of its own; the chat's line says so.
- A chat from an older Claude Code names no account. Its account shows as not known, never guessed from the clock.
- A chat on a login of its own (its own Claude Code folder, as `switchboard run` and `switchboard resume` give it) is marked as one when the session hooks heard its start or a prompt in it, or its status line showed numbers. Otherwise that is not known.
- A page belongs to the account its chat was on when it published it (the session hooks note each publish). A page made after the point the look has read to shows with its account not known.
- "Has not used it on this Mac in the last 7 days" is said only when the look has read every chat of those days to its end. While any is left, it says not known.
- A chat the look has not read to its end yet is listed apart, with only its title, its id and "still reading": the account it is on is not known until then, and an account's counts are of the chats read so far ("no chat read so far is on it", "at least 41 turns"). A chat whose last line is still being written counts as read up to its last whole line; the next look takes that line once it is finished.
- A turn is one of the chat's own replies, counted once even when a fork copied it into another chat. Helpers' replies are not counted.
- It is as fresh as the last look. The command says how old that is when it is over a minute.

## Running as another account

`switchboard run NAME -- ARGS` runs `claude ARGS` as another account, and leaves alone the login every other session uses. For example, `switchboard run work -- -p "summarize the open issues"`.

A run's environment carries nothing that would put Claude Code on an API key, a token, a cloud provider or a named profile instead of the account's login: those variables are left out of it.

The command gets a private, temporary Claude Code folder, with that account's login in a Keychain item of its own. When it ends, Switchboard saves the login back if Claude Code renewed it, then removes the folder and the item. While it runs, auto-switch never moves Claude Code onto that account. With the account Claude Code is already on, it runs `claude` on your own Claude Code folder. What your settings set there still applies to it: a key in their `env` is used by a run started with `-p`, and `switchboard doctor` names it.

The private folder links to your own Claude Code folder (`~/.claude`, or `CLAUDE_CONFIG_DIR`) for what every account shares, so the run has your chats and memory, follows your instructions, settings and hooks, and what it writes there stays when it ends. Only what is in your folder is linked:

- `projects` (chats and memory), `history.jsonl` and `paste-cache` (what you typed and pasted), `file-history` (checkpoints), `tasks`, `plans`
- `CLAUDE.md`, `rules`, `settings.json`, `keybindings.json`, `themes`, `agents`, `commands`, `output-styles`, `workflows`, `agent-memory`, `hooks`
- each of your skills, one by one, and your plugins' files (`plugins/cache`, `plugins/marketplaces`, `plugins/data`)

Copied, not linked, so a change made in the run stays in the run: your plugin records (`plugins/installed_plugins.json`, `plugins/known_marketplaces.json`); and from your `~/.claude.json`, your MCP servers for every folder and the entry for the folder the run starts in (whether you trust it, the tools you allowed, its MCP servers). The run's own `.claude.json` holds the other account's identity.

Never shared, because it belongs to one account or one window: your login (`.credentials.json` and the Keychain), `~/.claude.json` itself and its `backups`, skills and plugins synced from claude.ai, the organization's cached settings and limits, `/usage`'s counts, the MCP sign-in cache, Claude in Chrome's connection, running windows' files (`sessions`), background chats (`daemon`, `jobs`), and logs and caches. A run's artifacts, Claude Docs, claude.ai connectors and cloud chats are that account's.

A name in your folder that is your own link to somewhere else, such as settings kept with your dotfiles or a skill a skills manager put there, is linked as you set it up. If there is no `projects` folder yet, it is made first, so the run's chats stay. A run stops before anything is made when an entry leads back to your Claude Code folder, to a folder above it, to your login or identity file, or into Switchboard's own folder, and when your settings would run it on an API key, a token, a cloud provider or a named profile (`env` or `apiKeyHelper`) instead of the account's login. `switchboard run NAME --bare` starts it with none of your folder, as runs were before.

Taking the folder down never follows a link: each folder in it is opened without following links and emptied from there, so a link is only ever removed as a link, and your files stay as they are, with what the run added. If something replaced one of the run's links with a real file or folder, the folder is kept as it is (only the run's own login file goes), and History and the terminal say where. Claude Code itself writes your settings through the link and won't write over one.

`switchboard resume CHAT` opens a chat again as the account it started under: Claude Code writes that account into each chat's own file. On the account Claude Code is on, it is `claude --resume`; on another, it is the same through a run, in the folder the chat ran in. Back on its own account, the chat's artifacts, Claude Docs and connectors answer again, and the earlier reasoning that only that account can read is read again. A chat that a running Claude Code window holds (Claude Code keeps a small file for each running window, naming its chat), or that was written in the last minute, or has a turn still open in the last 15 minutes, is taken to be open in another window, and is not opened a second time: two windows writing one chat can lose messages. `--fork` continues it in a copy.

### A run that keeps its chat apart

`switchboard run NAME --no-history -- ARGS` links all of the above but the chat history: `projects` (chats, and the memory Claude Code keeps with them), `history.jsonl`, `paste-cache`, `file-history`, `tasks` and `plans`. Claude Code writes those in the run's own folder, and they go with it when the run ends. Your instructions, settings, hooks, skills, plugins and MCP servers come along as usual, which is what sets it apart from `--bare`. With the `run_history` setting at `apart`, every run is made this way, and `--history` makes one run shared again.

The account Claude Code is already on always runs on your own folder, never in a private one: two copies of one login can end each other's sign-in when one of them is renewed. So a run as that account can't keep its chat apart. Named with `--no-history`, it starts nothing, says why and exits 6; with only the setting, it runs on your folder and its first line says the chat is kept. `--strict` asks the same of any run: a script that must know its run was apart gets exit 6 instead of a run on your own folder.

### A folder that runs as one account

`switchboard folder NAME` sets the folder you are in, and every folder inside it, to run as that account: `switchboard run -- ARGS` there needs no NAME, and its first line says which account and which folder set it. The nearest folder above wins, and a NAME you type wins over both. A folder is kept by its real path, so a link to it, a trailing slash or `..` find the same entry, and only for this Mac, in `~/.switchboard/folders.json`. Removing an account takes its folders with it. Auto-switch never reads these folders: they decide only which account `switchboard run` starts as.

`switchboard resume` is not changed by any of this: it opens a chat as the account it started under (or `--as NAME`), whatever folder you are in and whatever `run_history` says.

## Other assistants

`switchboard continue` lets you carry on in another assistant: the chat in this folder goes on in Codex, OpenAI's app, beside Claude Code (or from Codex to Claude Code). Each is a provider on one board, `switchboard providers`, and the same commands work for each: the provider is a word after the command. Nothing moves on its own. Every move starts with a command you type, and `switchboard back` brings a note of what was done there to the chat you left.

**What a note holds.** Switchboard writes the note itself, on this Mac, from the chat's own file, with no model call: no assistant has to write it. It holds where the folder stands (its git branch, last commit and changed files, and the names of the project's rule files, not their text), what you asked (newest last), the latest plan when the chat had one, where the assistant got to, its last steps in more detail, the app's own summary of what came before, a record of the rest, the files and links it named, earlier notes of the same piece of work, and a closing section on what did not come across. To write where things stand, Switchboard runs git in the folder, with the folder's hooks and its file monitor turned off; a folder's own git settings can still make git start a program, as they can when you or your editor run git there, so carry on only from folders you trust. It leaves out the assistant's private reasoning, pictures, the text of web pages it fetched, and what a tool read from a file that usually holds a secret (`.env`, keys, credentials, `~/.ssh`, `~/.aws` and the like). Anything else that looks like a secret (a key or a token by its shape, a password in a line, a value your shell holds under a secret's name) is taken out as well as Switchboard can. That is best effort: the question and every line that says the note is made count the places that came out.

**Where it is kept.** In `~/.switchboard-notes/`, beside Switchboard's own folder and never in it: one folder per piece of work, the note and a small record of it, which only you can read. A note goes after 30 days, a job's answer after 7. When the next app asks to read a file outside your folder, that is the one folder to allow: it holds notes and answers only, never a login. A plain uninstall keeps it and says so; `--all` removes it.

**Your yes.** A note goes to another company's app only after your yes for that folder and that provider. It is asked once, at a terminal, after the note is made, with its size: `y` is yes for this folder from now on, `n` removes the note, `s` shows it first, and `never` removes it and keeps this folder's chats off that provider until `switchboard allow`. One yes covers a folder's chats and its jobs (`switchboard hand`), and both questions say so. `switchboard stay PROVIDER` keeps a folder's chats on one provider. No flag gives the yes. A command run by an assistant's own shell tool, with no terminal, can use a yes you already gave, but never gives one, and it starts nothing: no app, no job and no Codex helper. It prints the line to run instead. `switchboard allow` is answered in a terminal only, yet a program that opens a terminal of its own can still pass that check: an assistant's own permission prompt, when it asks before running a command, is the real wall.

**The next app.** It starts where the chat's work last ran. A chat is listed under the folder it was started in, and its assistant often moves into another folder as it works: then the next app starts in the folder the chat's work moved into, and the command says so in one line before it starts anything. Your yes for the chat's own folder covers the folders inside it. A folder outside it needs a yes of its own: at a terminal Switchboard asks before it runs git there or starts anything there; otherwise, or when you say no, it uses the chat's own folder and says how to allow the other. It never uses `/`, your home folder or a folder that holds it. A `never` or a stay for either folder is honoured. Opening the chat you left again (`switchboard back`) uses the folder it was started in. The next app runs on its own sign-in, with its own sandbox and approvals: Switchboard passes no flag that loosens them. Its first message is fixed words and the note's path. It gets your environment without the names that would put it on an API key or a cloud account (`OPENAI_API_KEY`, `CODEX_API_KEY`, `ANTHROPIC_API_KEY` and the like), and the command says so when one was set. Switchboard never runs a copy of an app older than the one that wrote its chats, a copy in a folder other users can change, or the copy an app keeps for itself.

**Text that gives orders.** A chat can hold words from a web page, a file or a tool that try to give the next assistant orders. The note quotes everything, marks its own headings, keeps your words apart from the rest, and tells the next assistant to read all but your words as information and to ask you before any step that cannot be undone. That lowers the risk; it does not end it.

**Jobs.** `switchboard hand codex -- JOB` runs Codex's exec mode in its read-only sandbox, approvals off, one job at a time, for up to 15 minutes, with only plain names from your environment (`PATH`, `HOME`, the language and proxy settings). Read-only means Codex cannot change files; it can still read files outside the folder. It runs only in a terminal, it keeps the job out of your Codex history, and its answer is kept for 7 days.

**On the page and elsewhere.** The page, `switchboard`, the menu bar and `switchboard doctor` show each assistant you added beside your accounts: whether it has room, its plan and its limits, one under another, and which one a chat would carry on to. A 5-hour window with no number to show has no line, as on the account rows. When the first assistant in your order is out and another one you added has room, one notification says so for that spell.

**Codex's numbers.** They come from Codex's own session files on this Mac: no program and no network. `switchboard providers --ask` asks Codex's own helper (`codex app-server`) for them now, only at a terminal, once you said yes there: at most every 5 minutes, one ask at a time, and longer apart after a refusal. It asks only for the account's plan and its limits; Codex may renew its sign-in while its helper runs.

**What Switchboard does with a note.** The move, and nothing else. It never uses a note to train anything and sends it nowhere itself. History records each move (where, the note's size, how many places came out), never a chat's words.

**Not tried on a real Mac yet.** Whether Codex and Claude Code read a note in `~/.switchboard-notes/` without asking; which app answers a `codex://` link when two are installed; whether `claude --resume ID "words"` takes the words as the first message; whether a Codex started in a terminal joins the desktop app's own background server; whether a second Codex helper beside the desktop app's is harmless; and a job on a ChatGPT plan.

## Auto-switch

Auto-switch moves Claude Code to another account before it reaches a limit.

- It never switches by itself while auto-switch is off. Auto-switch turns on by itself when a second account is in, unless you have turned it on or off yourself (on the page, in the menu bar, or with `switchboard auto`).
- It does not turn on by itself while another program on this Mac switches Claude Code's login.
- It watches the 5-hour limit, the weekly limit, and the own weeks of the models you pick on the page (Count a model), such as Fable's. Each has a switch line: 90% for the 5-hour limit and 95% for each week, unless you change them on the page or give one account lines of its own.
- Some moves go at once: the account in use at a line, its login refused, or Anthropic turning it away for now.
- Otherwise it uses the account that refills first, among those with room, and moves there before a line. The page's other orders, Most room and Stay, then refills first, stay on the account in use until it reaches a line.
- A move that can wait does. It goes only when Claude Code has been idle for 5 minutes, no artifact or doc was made on the account in the last 30 minutes, no chat used a claude.ai connector on it in the last 30 minutes, no chat watches an artifact made on it (a watch holds these moves while its chat is active, and until 6 hours after it goes quiet), both accounts' numbers are less than 10 minutes old, the last switch was 45 minutes ago or more, and the other account refills at least an hour sooner and has 10 points of room under every line. At most two of these in 6 hours. While one waits, the page says why ("Waiting: a chat used Google Drive as you@example.com at 3:02 PM"). Which account an artifact, doc, watch or connector call was on comes from the chat's own file when it says (Claude Code writes each change of login into it), else from the times Switchboard switched.
- It lands only on an account with room under every line, by 5 points or more. When none has room, it stays and says when the first one refills. Only when the account in use is completely stuck (a limit at 100%, its login refused, or Anthropic turning it away) does it move to one past its line that still has 5 points before 100%, and it says so.
- When Claude Code can't work on the account in use (its login refused or ended, or Claude Code said it is at its limit) and no account read just now has room, while the others' numbers can't be read (Anthropic turning the reads away, say), it does not stay stopped: it moves by what was last known of the accounts it could not read, the most room when last read first, inside the rules below, and the switch says it moved on older numbers. An account read just now is never chosen this way. It tries every account it could go to once more before, and reads the one it lands on straight after.
- Under 50 MB of free disk no switch begins, even when the account in use can't work: a switch needs that room to promise its undo. The page says the disk is almost full and that freeing space lets Switchboard switch again, History says it once, and when Claude Code can't work on the account in use, the notification for that names the disk as the thing to do.
- Each account can have a rule, set on the page (Settings, Each account) or with `switchboard auto last NAME` and `switchboard auto out NAME`; `switchboard auto in NAME` takes it away. The account's row says it: Used last, or Kept out of auto-switch.
  - **Use last.** Auto-switch goes there only when no other account has room. A move that must go at once looks, in order, for an account with room that is not used last, then one with room that is used last; only when the account in use is completely stuck does it go to one past its line, again those not used last first. So an account used last with room comes before running another past its line. A move that can wait never goes to one. While Claude Code is on one, with Refills first, a move that can wait goes to an account that is not used last and has 10 points of room under every line (the one that refills first), with no refill-time test, under the same waits.
  - **Keep out.** Auto-switch never moves Claude Code onto it, and never moves it away from it. At a line on it, with its login refused, or with Anthropic turning it away, Claude Code stays on it and the page says so: move by hand when you want to. Its limits are still read and shown, its sign-in is still renewed, and Use, `switchboard switch` and `switchboard run` work on it as on any other.
  - When the account in use has no room and the only accounts with room are kept out, it stays, and says which ones are kept out.
  - A rule is kept with auto-switch's own settings, under the account's id: a new sign-in to the same account keeps it, and removing the account takes it away.
- An account can have switch lines of its own, set on the page beside its rule (Settings, Each account) or with `switchboard auto line NAME --five-hour N --week N` (`off` puts it back on the shared ones). It is judged by them in place of the shared lines wherever those count: a move off it, the room it needs before a move lands on it, and the red on its bars.
- Accounts can have ranks, set on the page (Settings, Each account) or with `switchboard auto rank NAME N`. Auto-switch lands on rank 1 first, then 2, and on an account with no rank after every ranked one; inside one rank the order decides. Under Refills first, an account ranked before the one in use with 10 points of room under every line is a move that can wait, and a move that can wait never goes to a later rank. Use last and Keep out hold whatever the ranks.
- A third order, Stay, then refills first, stays on the account in use until it reaches a line, then moves to the account that refills first.
- Count a model can count several models' weeks, each against the model line.
- `switchboard switch --best` moves Claude Code now to the account auto-switch would land on, with the same rules, ranks, lines and fresh numbers but none of the waits above, and says why. When none has room, it says when the first one refills and moves nothing.
- After the Mac wakes, it waits for the network, then 30 seconds more, before it reads or switches.
- It runs in a process of its own, the one that reads the accounts, which the page starts and watches while an account is kept, auto-switch on or off: off, it reads and never switches. If it stops answering for 3 minutes while the Mac is awake, or finishes no pass for 12 minutes past the one it planned, the page starts a fresh one and logs why. One that ended starts again within seconds. When it has decided nothing for minutes past the pass it planned, the page, the menu bar and `switchboard` say "Auto-switch last decided 14 minutes ago. If it stays like this, run: switchboard doctor", and `switchboard doctor` says how to restart the page, which starts a fresh one.
- While the page is not running, nothing is read or switched by itself, and `switchboard doctor` says so. Its background job starts it again; when that does not, the menu bar item starts it after 3 minutes, unless you stopped it, and the page starts the menu bar item again when it stopped, unless you turned it off with `switchboard menubar off`. When another program holds the page's port, everything but the page goes on (the readings, auto-switch and the notes), and the page opens by itself once the port is free. A page that hangs is ended by its own watchdog and started again, never while a switch is written or a lost sign-in is put back.

With Notifications on, each switch sends one ("Switched to …"). Each switch also goes in History with its reason: `switchboard log`.

## Claude in Chrome

Claude in Chrome works only when the extension's claude.ai account is the one Claude Code is on, and it is added once in each Chrome profile. Once the extension is in one of your profiles, the page's Settings show how many accounts' profiles have it, and, for each account whose profile lacks it, a button that opens the Chrome Web Store in that profile. After a switch to an account whose profile lacks it, Switchboard says so.

While auto-switch is on, when a session uses Claude in Chrome and the extension follows another account that has room, Switchboard moves Claude Code to that account, at most once in 10 minutes. Otherwise it tells the session plainly. Switchboard never installs the extension and never signs anything in.

## What it puts in Claude Code's settings

Apart from what moving to another account writes ([A switch](#a-switch)), Switchboard changes Claude Code's files only for the switches below. Most of it goes in Claude Code's user settings, `~/.claude/settings.json`, and its instructions file, `~/.claude/CLAUDE.md` (both in `CLAUDE_CONFIG_DIR` when that is set). Switchboard keeps a copy of the settings file from before its last change (`settings.json.switchboard-backup`) and a record of what it added, so off takes out exactly that and leaves the rest as you left it.

| Switch | What goes in | At first |
|---|---|---|
| Status line in Claude Code | `statusLine`: Switchboard's command, run every 60 seconds too (`refreshInterval`) | On by itself, unless you have your own |
| Notifications | three hooks: `UserPromptSubmit`, `Stop` and `Notification` | On by itself |
| Session hooks | `SessionStart` and `UserPromptSubmit` hooks, and `PostToolUse`, `PostToolUseFailure` and `PreToolUse` hooks for artifacts, Claude Docs and Claude in Chrome | [Below](#session-hooks) |
| Sonnet for helpers | `CLAUDE_CODE_SUBAGENT_MODEL` set to `sonnet`, in `env` | Off |
| House rules | a short block at the top of CLAUDE.md | Off |
| Code map | a short block at the top of CLAUDE.md | Off |
| claude-mem | claude-mem's plugin, from its own installer | Off |

When `settings.json` is a symbolic link (kept with your dotfiles, say), nothing goes in by itself: the paths Switchboard writes are this Mac's, and the file may be used on other Macs too. The log says so once. `switchboard statusline on`, `switchboard notify on` and `switchboard hooks on` still put each in, through the link.

The status line and the hooks name the Python that turned them on. If that Python is gone later (the app that held it was removed, or an update chose another), the page writes Switchboard's own commands again when it starts and every 10 minutes, to run on its own Python. An entry Switchboard put in that was taken out of Claude Code's settings while it is still on in Switchboard is put back once, the same way; when it goes again within a day, it is left out, and the page and History say what that costs, how to put it back, and, for the hooks, how to keep them out (turn them off in Switchboard); the page and `switchboard doctor` say it for a day. Off still takes out exactly what went in, and a command of your own is never touched.

### Status line

Claude Code runs Switchboard's command at the bottom of each window and shows the line it prints:

```
● ana@work.example on Opus · 51% left · refills Sun 2 PM · next: ana@home.example
```

The account names come from Switchboard; the numbers and the model come from Claude Code. Claude Code runs it whenever the session changes, and every 60 seconds besides, so the line stays current while a session is quiet. Each run saves the numbers Claude Code handed it, and nothing else: that is how Switchboard knows the account in use without asking Anthropic. Claude Code hands over these numbers only on Pro, Max and Ultra plans, after a session's first reply, and only in a terminal: its VS Code panel runs no status line, so there the account in use is read from Anthropic like the others ([how fresh](#how-fresh-the-numbers-are)).

A status line of your own stays. `switchboard statusline on --replace` puts Switchboard's in its place, and `switchboard statusline off` puts yours back exactly.

### Notifications

Switchboard sends its own: a switch, an account near its limit or refilled, a login kept, auto-switch turning on, a sign-in 3 days and 1 day from its end and once it has ended, a lost sign-in put back, and "Plug in your Mac" when Claude Code works on battery under 25% or with the lid shut. When Switchboard is not doing its job for 5 minutes of awake time, one note says so, with the one thing to do: auto-switch stopped or deciding nothing (and "works again"), the account in use unable to work with no switch possible (and "can work again"), a Keychain dialog waiting for your answer, every account's numbers over an hour old (not while the Mac has no network, nor while Claude Code is without a sign-in), Claude Code without a sign-in Switchboard could not put back (and "signed in again"), another program holding the page's port, and the page stopped and started again by the menu bar item, or not. The three hooks add two from Claude Code: "Claude Code is done" after a turn of a minute or more, and "Claude Code needs you" when it waits on a permission prompt or a question. Helpers and workflow agents never send one.

The hooks keep only when each turn started (its session, its prompt's id and the time), for a day: never the prompt or the answer. macOS shows the notifications as Script Editor's, because they go through `osascript`. Turning Notifications off (`switchboard notify off`, or on the page) stops both kinds and takes the hooks out.

### Session hooks

They help a chat across a switch. At the start of a chat, Claude Code is told that accounts may move, how to reach an item as its owner (`switchboard owner LINK`, `switchboard open LINK` and `switchboard run OWNER -- …`), and that `switchboard chats` shows what every account's chats are doing; a resumed chat is told the account it started under and where its last request went. The first prompt after a switch is told which account the chat moved from and to, that the model's private reasoning from before may be missing while everything said and done is still there, and how to reach what the chat made under each account. When an artifact or a Claude Doc comes back "not found", the chat is told the owner and the exact command. When a claude.ai connector fails ("session expired", "is not connected", "connection closed before the tool call") in a chat that has moved, the chat is told, once per connector and move, what Switchboard knows, as plain facts and never as the cause: what failed; where and when the connector last answered (in this chat, and on this Mac under another account); which account the chat is on and since when; that connectors are added per account on claude.ai, and whether that account has had it answer on this Mac in the last 7 days ("not known" unless the page's look has read every chat of those days); and the way through: `switchboard run ACCOUNT -- -p "…"` for the chat, which moves nothing, only with an account the connector is known to have answered under, or `/mcp` for you. It says this only when the connector answered in this chat before the move and not since, or the look shows it answered under another account in those 7 days and never under the chat's, or the move was within the hour. Otherwise, and when the chat never moved, Claude Code's own error stands alone. A time from the chat's own file is its first request on that account ("this chat has been on B since 3:02 PM"); only a switch Switchboard made is said as "moved at". When a chat uses Claude in Chrome, the hook checks the extension's account first ([Claude in Chrome](#claude-in-chrome)). None of them ever tells a chat to sign in. Helper agents hear of no switch and no connector.

Which account a chat is on comes from the chat's own file: Claude Code writes into it the login the chat started under and each change of login, with the time. The hooks read only what was added since their last look (the page's look at every chat, `~/.switchboard/chats.json`, gives them a start), and at most the last 4 MB of a long chat they have not seen before. When the file says nothing, its newest change is under 90 seconds old and is not to the account Switchboard switched to (another program can make it flip back and forth), or it names no account Switchboard keeps, they go by the times Switchboard switched, and never take the account a chat started under for the one it is on. A switch is told once, whether the chat's file or Switchboard noticed it first.

When a chat publishes, creates or updates an artifact, or makes a Claude Doc, the hook notes it without a word to the chat: one line in `~/.switchboard/hooks/published.jsonl` with its link, the file it was published from, the time and the session. That is how a page made a moment ago opens as its owner ([Artifacts](#artifacts)). Noting it reads no login and uses no network, and the hooks keep each line a week or two. When a claude.ai connector answers, the chat's own small record notes when, the same way.

They go in by themselves at the first run, beside hooks of your own, which stay as they are. `switchboard hooks off` takes exactly them out, and they don't go back in by themselves; `switchboard hooks on` puts them back, and brings hooks put in by an older version up to date (`switchboard hooks` and `switchboard doctor` say when they are).

### Sonnet for helpers

Off until you turn it on: on the page, or with `switchboard models on`. It sets one thing in Claude Code's settings, `CLAUDE_CODE_SUBAGENT_MODEL=sonnet`, so helpers and workflow steps that name no model run on Sonnet instead of the chat's model. The chat keeps its own model. These keep theirs too: a helper Claude starts with a model named, a helper whose definition names one, the built-in Explore and Plan helpers, and forks. `switchboard models off` takes the setting out again.

A chat that is already open uses it for its next helper. Turning it off reaches an open chat only when it restarts. When the same setting is made somewhere else (Claude Code's managed settings, your own settings, or the environment Claude Code starts in), the switch says where and changes nothing. It needs Claude Code 2.1.251 or newer.

### House rules

A short block at the top of CLAUDE.md, between two marker lines: think before changing code, make the simplest change, touch only what was asked, check before saying done, and say what was not checked. It is Switchboard's own wording of what five rule sets share ([credits](credits.md)). Off takes out exactly those lines. If you edit inside the block, Switchboard leaves it to you.

### Code map

A short block at the top of CLAUDE.md that tells Claude Code to ask a code map before it searches or opens files. Switchboard does not map code itself: it names graphify or codegraph, whichever is on the Mac, and uses it as it is. When neither is, turning the switch on shows a plan to install codegraph (what, from where, how big), and installs only after you agree. That install puts codegraph in `~/.codegraph`, checked against a pinned checksum, and connects it to Claude Code only: an entry in `~/.claude.json` and a permission for its tools. Off takes out exactly what it added.

### claude-mem

claude-mem keeps notes from your chats for Claude Code to look up. When it is not on the Mac, turning it on shows a plan, then runs claude-mem's own installer, version 15.18.3, checked against npm's record of that version before it runs; a claude-mem you installed yourself is used as it is. Switchboard sets it to watch your own chats, not helpers', and turns its telemetry off.

claude-mem runs a model on your own Claude usage, and pauses when that passes 10% of your Claude Code use over 7 days (you can change the 10%). It also pauses when the account in use is at 85% of its weekly limit.

Off takes out exactly what the install added. Its notes stay in `~/.claude-mem`. Its search runs Chroma through uv, which keeps Python and packages in uv's own folders; turning claude-mem off leaves those.

## The page

The page is at http://localhost:7799; `switchboard page` opens it, and `switchboard update --port N` moves it. It listens on this Mac only and refuses requests from other websites.

A sidebar holds everything: Search, Accounts, Chats, Artifacts, Activity and Settings. Each is a view with its own address (`#accounts`, `#week`, `#chats`, `#chats/<email>`, `#artifacts`, `#artifacts/<email>`, `#activity`, `#settings`), so Back works and a link opens a view. In a narrow window the sidebar is a bar at the top, with a menu.

- Accounts: the account Claude Code is on, and when it was last checked ("checking…" while a read is under way; press it, or R, to read every account now). A row per account: its email, with its plan under it and how many chats that started on it were written in the last day (a click shows them), then its limits one under another (5-hour, only when there is a 5-hour number to show, and weekly), and In use, Use or Next. Each limit is one line: how much is used, a bar, and when it refills (in a very narrow window, when it refills goes under the bar). When a reading is more than 15 minutes old, its age is under its numbers. A row that needs you shows one button, Sign in or Set up, with the reason on hover. Each bar has a thin mark at its switch line and turns red at or past it. A model's own week, such as Fable's, has no line: the weekly line's hover says each one, and when auto-switch counts it and it is at or over its switch line, its name and percent are a short red note at the end of the weekly line. When, at the pace of its use so far, an account's weekly limit would be full before it refills, its weekly line says when, in its refill's place ("Full by Thu 2 PM"; the refill on hover): the share of the week used so far, carried on at the same rate, from a reading under an hour old, once the week has run 12 hours and 10% of it is used. History says it once that week. A week that lasts says nothing. A spend limit, on a plan that has one, is a line of its own under the weekly one ("Spend 41%", its bar, "$412 of $1,000"), with no switch line: it never turns red. It takes the 5-hour line's place when more of it is used, so a row still has two limit lines at most. Switchboard learns it from Claude Code's own numbers, so only for the account in use. Above the accounts is the switch line: Auto-switch at [90 %] 5-hour [95 %] weekly, the 5-hour field only when an account has a 5-hour limit. A model's week has its field in Settings, Switch at. Type a number from 50 to 99.9; Enter or leaving the field keeps it, Escape puts the old one back. Each row's menu holds Use, a terminal as that account, claude.ai in its profile, a short name to type in its place, its place in the order, and Remove.
- Your week, under the accounts: the last 7 days of Claude Code use by hour, at every window width, stacked by who did it: workflows, helpers and your own chat turns. On the same time axis: each limit reached (a red dot), each switch (a tick), the average hour with use (the line marked avg, with 2×, 4× and so on above it) and the busiest hour, named. Point at an hour, or use the arrow keys, to read it: how it stands against the average, who did it, its projects, its models, the kind of work, how many agents, workflows and tool calls ran in it, how its tokens divide (re-reading context, storing it, Claude's replies), the account Claude Code was on, and any limit reached or switch in it. The table button shows every day's numbers. Under the chart, up to three highlights made only from those numbers, then the week by project, by what agents did and by model. Use is tokens weighted by today's prices: a cache read is 0.05 of an input token, a cache write 1.25 (2 for a 1-hour one), output 5.
- Chats: the chats of the last 7 days, each under its home, the account it started under; the account Claude Code is on first, and chats that started on an account Switchboard doesn't keep, or one not known, last. A row is the chat's title (or its folder's name), Working or when it last wrote, and, only when it is not on its home, where it is now and since when. A second line shows only what it holds out of reach there: a connector that answered it under another account and has not answered under the one it is on (for example "Google Drive answers on work@example.com"), and the artifacts it made under another account. For a chat away from home, Reopen at home opens it in Terminal with `switchboard resume`, as the account it started under; it waits while the chat is working, and the page says so instead of opening a second window on a chat a window holds. Its menu copies that command. Chats that last wrote over a day ago fold under Earlier. Until the first look has read every chat, the page says how far it has got, shows no counts, and shows a chat it has not read to the end by its name alone.
- Artifacts: a folder per account, named by its email, and Not matched yet while it holds any. In a folder, each artifact is a tile: a picture of its page when Switchboard has one, else its title. One click opens it as its owner. The search covers every folder, and a link pasted there opens as its owner too.
- Activity:
  - History: what happened.
  - Past chats: a search of your chats on this Mac; a match copies its `claude --resume` command.
- Settings, grouped by what each is for: Switching, While Claude works, In Claude Code, Links, Keys and Accounts. Each shows its command where one exists, and its key (in `~/.switchboard/settings.json` or Claude Code's settings) on hover; search finds a setting by its key too. Copy as commands copies them all. The last line is the version and the page's address. Chrome profiles are facts: each account opens in the profile signed in to it, and a row offers Set up only when an account has none.

Every surface names an account by its whole email: the page, the menu bar, the terminal, the status line and the notifications. When two accounts share an email (one person in two organizations), each adds its organization after the email: maya@northwind.example (Northwind). A command given that email says it fits two accounts, and to give one a short name (its number works too, until the list changes). The name the page shows, with the organization, works in a command too. A short name (`switchboard alias`) is only something to type, in ⌘K or in a command, in place of its number or email.

Keys: ⌘K finds a view, an account, a folder, an artifact or a setting (type part of an account's email, or its short name, and press Enter to move Claude Code there); `/` finds in the view; G then A, W, C, P, L or S goes to a view (W: your week); R reads the limits again; `?` lists the keys; Escape closes, or leaves a folder.

The links line, on Artifacts and in Settings, says what happens to a link you click in another app: when another app takes clicked links and sends them to the page, they open as their owner while the page runs; when a browser is the default, they open there, not as their owner. Either way it offers to make Switchboard Links the default, which works even when the page is closed.

When Switchboard is slow to answer, as on a busy Mac, the page keeps the last numbers on screen and says how old its last answer is; when Switchboard isn't running, it says that instead.

Keep Mac awake is automatic: while Claude Code works, Switchboard holds `caffeinate`, and lets go two minutes after the work stops. To turn it off, set `"awake": false` in `~/.switchboard/settings.json`; the page then offers Turn on. macOS still sleeps on battery with the lid shut.

## The Mac app

Switchboard.app is the menu bar item's app. The installer puts it in /Applications when it can write there without a password, else in ~/Applications. Opening it from Spotlight, Launchpad or Finder starts the menu bar item when it is not running, and opens the page when it is; there is never a second item.

The item is Switchboard's S. A small dot at its top right is orange when the account in use is at or over a switch line, and red when something needs you, such as a sign-in that has ended, no account with room, or Switchboard not running. The first time it starts, it asks macOS for the place at the right end of the menu bar, toward the clock, where a notch does not cover it; a place you choose is kept. The menu lists every account by its whole email, with In use, Next or Use and its bars (5-hour only when there is a number, and weekly), and Sign in again for a sign-in that has ended or ends soon; then Auto-switch (with a line under it when the page has something to say, such as what a move waits for, or, while it is off, that reading the accounts is stuck), Add account (it opens the page's Add form) and Open Switchboard. When it was last checked and when a limit refills are on the page. The item reads the page every 15 seconds, every 2 seconds while its menu is open, and asks Anthropic nothing. The menu has no Quit, and an item that stops is started again. `switchboard menubar off` turns it off, across logins and updates; `switchboard menubar on` brings it back. When a full menu bar puts it behind a MacBook's notch, one notification each login says so, while Notifications are on.

`switchboard update` replaces the app and starts the item again; your accounts stay. The uninstaller removes the app only when this install made it. An app named Switchboard.app that isn't Switchboard's is never touched: the installer says so and puts the app in the other Applications folder.

A menu bar manager (Ice, Bartender) can keep the item in view when its app is in /Applications. From ~/Applications, a manager that hides anything may hide it too: macOS 26 treats an app outside /Applications that way.

## How fresh the numbers are

- The account in use, in a terminal while you work: Claude Code hands its own numbers to Switchboard's status line as the session changes, and every 60 seconds. The page shows them within 5 seconds, the menu bar within 15 (2 while its menu is open), and they say "now" for a minute after they change.
- The account in use otherwise (Claude Code's VS Code panel, which runs no status line; Claude Code idle; or the status line yours or off): Switchboard reads it from Anthropic once the status line's numbers are more than 3 minutes old, or when there are none. That is every 5 minutes; near a switch line, every 90 seconds for the first few reads, then every 3 minutes for as long as it stays near, never a stop.
- While the page is open: opened, or back in view, it asks for every account at once when the account in use was read more than a minute ago, or another account more than 5 minutes ago; while it stays in view, it asks for the account in use about every 3 minutes, or 5 minutes after an ask that read nothing back (Anthropic said to wait, or the read failed). Read again (or R) asks for every account at once. An account read in the last minute is not asked again, so several open pages make one read. The header says "checking…" until the answer comes, then "checked just now".
- Every other account: every 5 minutes; while the account in use is near a switch line, as often as the account in use (a switch may come, and the account it goes to must be fresh); every 15 minutes while the account in use is far from its lines and Claude Code is idle. An account at a limit is read at most every 10 minutes.
- As often on a busy Mac; a third as often on battery under 25%.
- All of this whether auto-switch is on or off, and with one account: off, Switchboard reads every account and renews the saved logins of the accounts you are not using, and never switches.
- A reading reaches the page, the menu bar and the terminal at their next look, within seconds, however busy the Mac is.
- Each account shows when it was last checked ("checked just now" for under a minute): the last read that was answered, even when it changed none of the numbers. A number Switchboard can't vouch for shows as not known, never as a guess. An account with no 5-hour limit (some plans report none) has no 5-hour line, and its weekly line's hover says Anthropic reports none for it. A reading too old to show has no 5-hour line either: its weekly line is a dash, with its age under it. Numbers brought from another Mac with `switchboard readings take` show for 10 minutes (an hour at most, with `--for`), marked "from another Mac" with their real age; auto-switch and `switchboard switch` never decide on them.

Why not every account every minute: Anthropic turns an account's readings away for a while when they come too often (at about 28 to 30 an hour), and then that account goes unread for 6 to 75 minutes. So every read of an account follows one pace: one comes back every 3 minutes, and up to 4 can be saved up. The schedule and the page's asks together read an account at most 23 times in any hour; with the reads just before a switch, never more than 24. When Anthropic says to wait, Switchboard waits as long as it is told, up to 75 minutes, and marks those numbers as held back: the real ones can only be higher.

## Keys and the gateway

For when every account is out. Add an API key with `switchboard keys add NAME`, or on the page under Settings, Keys. It goes into your Keychain; Switchboard keeps only its name and last four characters. Turn the gateway on in the same place, then `switchboard claude` starts Claude Code on your keys, in that terminal only. Plain `claude` stays on your accounts.

The gateway listens on this Mac only (127.0.0.1). It refuses any request that carries a subscription login, with no way to turn that off (the [FAQ](faq.md) says why). Requests through it are billed by the key's provider. It has been tested against a stand-in, never against Anthropic or OpenRouter.

Switchboard has no spending limit of its own. Set a monthly limit on each key at its provider before you turn the gateway on.

## Privacy

What it keeps:

- Logins, in your Keychain: one item per account, named `Switchboard login`, its last two earlier logins (`Switchboard login (previous)`), and `Switchboard recovery`, which holds a login that is not safely kept anywhere else yet (a renewed one until it is saved, or the one a switch replaced until it is known whose it is). Claude Code's own item holds the account in use. Switchboard's files in `~/.switchboard` hold no login, except a recovery file when the Keychain refused one (only you can read it; it goes when the login it protects is safely kept, when you remove that account, or when you remove Switchboard with `--all`). A recovery copy of the login Claude Code was on, kept before a switch replaced it, when no saved account holds that login and Claude Code no longer does, is the only copy left: `switchboard leftovers` marks it needed, and it is removed only when you name it with `--only-copy`.
- An accounts file you export, wherever you put it: your accounts' logins, protected with your passphrase, until you delete it (Switchboard never does). `switchboard export - --plain` prints them unprotected, to standard output only.
- API keys, in your Keychain, named `switchboard-gateway`. Switchboard's files keep only each key's name and last four characters.
- In `~/.switchboard`, which only you can read: your settings; each account's email, organization, name and place in the order, with a short fingerprint of its login (a hash, not the login); browser profile names and artifact links, with the file each was published from and a small picture of each page (previews); History; each account's latest numbers and 7 days of them; the chat search's index; the folders you set to run as an account; numbers you took from another Mac, while they are shown; what the last daily look for a newer version found; and which root certificates macOS called trusted at its last full look (their SHA-256 digests, never a certificate).
- For each chat the session hooks saw, a small record kept a week after its last use: the account it was last told about, whether it runs on a login of its own, how far its file was read, the organization and time of each change of account in it, and the names of the claude.ai connectors that answered or failed in it, with times. Of a chat's file the hooks read only the lines that name an account (and, on the first prompt after a switch, its last 4 MB for the artifacts and docs it made); the loop behind auto-switch, which runs whether auto-switch is on or off, reads the same lines and the names of the connectors a chat called, and keeps them only in memory. Never what a message said.
- History never keeps a login, a key, a prompt or a chat's text. Anything shaped like a key or a token is masked, and an artifact's title is cut to 60 characters.
- The chat search indexes your prompts and Claude's text replies, starting the first time you search. Tool output and helpers' chats are left out.
- History's Work reads Claude Code's history on this Mac and keeps numbers, model and tool names, and chat titles: never what a message said.
- [Chats](#chats) reads the chat files of the last 7 days (further with `--days`) and keeps, in `chats.json`: each chat's file and how far it was read, the organization and account id it started under and each organization it was on, with times (its newest few hundred changes, and how many moves the older ones held), its folder, and when it last wrote; and per account, the claude.ai connectors that answered under it and when. In `chats-view.json`: each chat's title, the connectors it called with the account each answered or failed under, how many helpers it has and when their folders last changed (each folder named by a hash), its last turn on each account, the turns of the last day per quarter hour, and a short hash of each request id for a day. Never a message, a tool's input or a tool's output.
- `switchboard run` reads, from your `~/.claude.json`, your MCP servers and the entry for the folder it starts in, and copies them into its private folder, which goes when it ends. `switchboard resume` reads, from the chat's own file, the account it started under, the account it is on and the folders it ran in (named in its last lines, its account lines and its first lines), and keeps nothing of them; it opens the chat in the folder Claude Code keeps it under, else in the one its last lines name; and it reads Claude Code's own list of its running windows (`sessions/` in its folder) for the chat's id. The file that opens Terminal on a chat holds the chat's id. The page's Reopen at home first looks, as `switchboard resume` does, for the chat's file and whether a window holds it or is writing it, and keeps nothing of it.
- Each account's limit readings for 8 days, in `~/.switchboard/readings.jsonl`: its 5-hour, weekly and model percents and when they were read, a line only when one changed, so the page can draw them over your week's work.
- For other assistants, in `~/.switchboard/providers/`: your order, the providers you added, your yes or never per folder and provider, a ledger of each move (ids, paths, times, sizes and counts, never a chat's text) and each provider's latest numbers. In `~/.switchboard-notes/`: the notes of chats you carried on (30 days) and the answers of jobs (7 days). Only you can read them. After `switchboard back`, a Claude chat's next message may carry a pointer from `~/.switchboard/hooks/notes/`: fixed words, times and the note's path.

What leaves the Mac:

- To Anthropic: each account's limits, its login's renewal, and a lookup of which account a login belongs to, at the addresses Claude Code uses, under Switchboard's own name (`Switchboard/<version>`).
- To a key provider you add: the requests you send through the gateway.
- To OpenAI, through Codex: the note or the job you asked for, and Codex's own request for its limits when you run `switchboard providers --ask`. To Anthropic, through Claude Code: a note of a Codex chat you carried on in Claude. Switchboard sends nothing itself.
- With claude-mem on: what its model reads from your chats, through your own Claude login.
- For a preview: the scripts, styles and fonts your published page names, fetched from the code and font sites claude.ai allows (cdnjs.cloudflare.com, cdn.jsdelivr.net, unpkg.com, cdn.tailwindcss.com, code.jquery.com, fonts.googleapis.com, fonts.gstatic.com). No other address can be reached while a page is drawn.
- A look for a newer version, only when you run `switchboard update --check`, or once a day when you turn that on (`switchboard config set update_check daily`; it is off until you do). It asks only the place an update would come from: for an install from the web, the program's version line beside the installer's address, under Switchboard's own name (`Switchboard/<version>`) and with nothing else; for Homebrew, Homebrew's own list; for an install from a folder, that folder, on this Mac.
- Nothing else, besides the downloads below. No telemetry.

What it downloads:

- The installer and `switchboard update`: the program, from GitHub, not yet checked against a checksum; Switchboard's own Python, from python-build-standalone on GitHub, when the Mac has no Python it can use; and PyObjC's two packages, from PyPI, for the menu bar item. The Python and both packages are checked against a pinned SHA-256.
- The code map switch, after you agree to its plan: codegraph, from GitHub, checked against a pinned checksum.
- The claude-mem switch, after you agree to its plan: claude-mem, from npm, checked against npm's record of that version; the packages claude-mem needs, from npm as npm resolves them; and Node.js, Bun and uv, from nodejs.org and GitHub, when the Mac has none, each checked against a pinned checksum. claude-mem's and codegraph's own telemetry is turned off.

| What | Where |
|---|---|
| The program, what it runs on, your settings, History and logs | `~/.switchboard` |
| The command | `switchboard` in `~/.local/bin` (in `/usr/local/bin` when only that one is on your PATH; with Homebrew, in Homebrew's bin folder, where it runs the one in `~/.switchboard/bin`) |

## Update and remove

`switchboard update` runs the installer again from where it came (its address, or the folder you installed from; with Homebrew, it runs `brew upgrade switchboard`) with the choices you made: no background jobs, no menu bar item, no link app, Switchboard's own Python, the page's port. It never opens the page or runs the first run again. `--link-app`, `--menu-app`, `--no-menu-app` and `--port N` change a choice, and the change is kept for later updates.

The uninstaller stops the menu bar item and the page (a switch under way finishes first), and removes the background jobs, the command, Switchboard.app, the link app and the program. It removes an app only when it is Switchboard's own. Before the program goes, it puts back what Switchboard changed in Claude Code (the status line, the hooks, Sonnet for helpers, house rules, the code map and claude-mem's settings) and takes out claude-mem and codegraph when Switchboard installed them. claude-mem's notes in `~/.claude-mem` stay. If Switchboard Links is your default browser, macOS asks which browser gets it back.

A plain uninstall keeps your settings, accounts and History in `~/.switchboard`, with the chat search's index and the pictures of your pages, and the accounts' logins in your Keychain, so a reinstall picks them up. It leaves a copy of itself there too, and its last line is the command that removes the rest: `sh ~/.switchboard/uninstall.sh --all`. `--all` removes those too, with everything else in `~/.switchboard`, the pictures of your pages included, and the notes folder beside it, `~/.switchboard-notes` (a plain uninstall keeps that folder and says so). With Homebrew, `brew uninstall switchboard` runs the uninstaller and `brew uninstall --zap switchboard` runs it with `--all`. Homebrew also runs a cask's uninstall step before every upgrade and reinstall; then Switchboard is left as it is, and the installer that follows keeps it. When something can't be put back, see [troubleshooting](troubleshooting.md#the-uninstaller-says-something-could-not-be-put-back).

## Limits

- macOS only.
- The Work shares under History are worked out from Claude Code's history on this Mac, not from Anthropic's own accounting.
- A renewed login that is waiting to be saved, and can't be saved or read, is said only when you switch or run to that account: until then the page shows the account as fine. An account already marked as needing a sign-in is looked at again for a waiting login only by `switchboard run`. A renewed login that neither the Keychain nor the recovery file would take is held in memory, and is lost if Switchboard stops before its next try: then that account needs a sign-in.
- claude-mem 15.18.3 and codegraph v1.6.2 were each installed by their switch and taken out again once for real, in a throwaway home: every file came back with the same contents except claude-mem's notes, and nothing was left running. Not tried for real: the default `~/.claude.json`, a Node already on the Mac, no internet, an install cut short, the checked claude-mem package (tried with stand-ins), and a week of use.
- Chats were read once over a real Mac's chat files, read-only: each chat's accounts matched a whole read of its file. Pages a chat made and chats on a login of their own were tried with stand-ins only.
- Tried on one real Mac, in daily use: switching by hand and by itself, and keeping and renewing logins. Not tried on a real Mac yet: signing in again from the page as it is in this version, each auto-switch rule above one by one, `switchboard run` and `switchboard resume`, the session hooks and Claude in Chrome's switch. Each is tested with stand-ins for the Keychain, the network, Chrome and Claude Code.
- Not yet: a short install address, a PyPI package. `packaging/README.md` says what a package would need. The Homebrew cask was tried with a local copy of the tap, not yet from GitHub.
